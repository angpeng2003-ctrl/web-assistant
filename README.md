# 建站助手

给做网站的人用的本地客户台账和流程工具：记客户信息 → 准备账号 → 一键建项目文件夹并写好建站规则 → 记录交付 → 确认代码都传到 GitHub 后清理本地文件夹。

需求整理交给 Claude：把和客户聊的录音转文字、截图直接丢给 Claude。建站助手不写网站代码、不运行客户网站、不安装依赖、不提交也不推送代码。

## 启动

需要 Node.js 20 或更新版本，和 Git（只用来检查上传情况）。**没有第三方依赖，不用 `npm install`。**

- 双击 `启动建站助手.cmd`，会自动打开浏览器；或者
- 在这个文件夹里运行：

```powershell
npm start
```

然后打开 http://127.0.0.1:4520 。关掉命令行窗口（或按 Ctrl+C）就停止。只在本机 `127.0.0.1` 上监听，同一网络里的其他设备访问不到。

## 四个步骤

1. **客户信息**：名字、负责人、电话、地址、邮箱、费用，自动保存。
2. **账号与准备**：买好的域名和每年价格，加一张固定的账号清单（Gmail、GitHub、主仓库、Vercel、域名注册商、Resend、Supabase），每行只填账号名，旁边写着要你自己核实什么。都不强制，填了的才写进交付报告和建站规则。不显示状态，不记密码。账号属于客户，费用由客户承担。
3. **工作环境**：一键在 `网站建设` 下新建项目文件夹，写入 `CLAUDE.md`（建站规则：先用 UI UX Pro Max 定设计、客户依据、密钥、推送、交付规矩）。也可以选已有文件夹，同名但内容不同的文件会让你选覆盖（旧的先备份）、另存新版本或取消。规则模板所有客户共用，可以在这一页改，`{{店名}}`、`{{编号}}` 会自动替换。
4. **交付与维护**：记录交付日期（售后从首次交付起算，以后不会被悄悄改）、交付报告（英文，给客户看；打印或存 PDF。固定文字和默认账号清单自动是英文，“交付信息”里自己填的几栏请用英文写。报告里有网站、账号、售后、价格和付款、平台费用几段；不设签字栏，打印出来在空白处手写签字即可）、维护请求，以及**上传检查和清理本地文件夹**：
   - “检查 GitHub 上传”会从 GitHub 取回最新状态，看有没有没提交的改动、没加进仓库的文件、没推送的分支和提交、本地暂存、没推送的标签，并列出被 `.gitignore` 排除、只在本地的文件（例如 `.env.local`、`_原素材/`）。
   - 已记录交付、检查全部通过后，才能“删除本地文件夹”：要输入文件夹名确认；有只在本地的文件要打勾确认；删除前会当场再检查一次。`node_modules`、`.next` 这类能重新生成的直接删，其余整个文件夹移到 **Windows 回收站**，需要时可以还原。

网址会记住当前客户和步骤（例如 `#/JZ-0001/workspace`），刷新不丢，浏览器“后退”能回上一步；顶栏一直显示保存状态；跟随系统浅色 / 深色模式。界面规范见 `docs/design-system.md`。

## 文件夹

| 位置 | 内容 |
|---|---|
| `server/` | 本机服务（Node 内置模块）；`git.js` 是上传检查和清理 |
| `public/` | 网页界面（原生 JavaScript，不用构建） |
| `shared/` | 浏览器和服务端共用的密钥识别 |
| `tests/` | 验收测试，`npm test` 运行（用临时文件夹和本地裸仓库，不碰真实数据和回收站） |
| `data/` | **客户数据，不提交** |
| `docs/` | 设计规范；交接文件和路线图只留在本机（带客户名，不提交） |

## 数据在哪里、怎么备份

- 每个客户一个文件：`data/clients/JZ-0001.json`。客户之间互不影响。
- `data/clients/*.json.bak`：每次保存前自动留的上一版。
- `data/rules-template.md`：你改过的规则模板（没改过就用内置默认）。
- `data/backups/`：在“工作环境”里选择“覆盖”时，被覆盖文件的旧内容；以及改版前的数据副本。

**备份**：停掉服务，把整个 `data/` 文件夹复制到别处。**恢复**：停掉服务，把备份的 `data/` 放回来再启动。**换电脑**：复制整个 `建站助手` 文件夹（含 `data/`），装好 Node.js 和 Git 就能用。

## 配置

复制 `config.example.json` 为 `config.json` 再改（`config.json` 不提交）：`port`（默认 4520）、`dataDir`（默认 `data`）、`workspaceRoots`（能建 / 选项目文件夹的范围，默认上一级的 `网站建设`；建站助手自己的文件夹永远不能选）。也可以用环境变量 `JZ_PORT`、`JZ_DATA_DIR`，或命令行 `node server/index.js --port=4521 --data=demo-data`。

## 安全设计

- 客户输入一律按纯文本显示；页面有内容安全策略，只运行本机脚本。
- 服务端拒绝未知字段、限制长度；只接受本机页面发来的修改请求。
- 疑似密码、令牌、API 密钥、私钥：浏览器和服务端两处拦截，不保存；写文件前再清一遍。
- 写文件：只在允许范围内的真实文件夹里写，不写链接或联接点，写入前核对文件没被改过，不删除已有文件。
- Git 只用只读命令；关掉 fsmonitor、不弹登录框；显示的远程地址会去掉里面可能带的账号密码。
- 删除本地文件夹只走“检查通过 + 名称确认 + 回收站”这一条路；不能删允许范围的根文件夹和建站助手自己。

## 已知限制

- 删除只支持 Windows 回收站。文件夹特别大时，移到回收站可能要等一会儿。
- “只在本地的文件”靠 `.gitignore` 判断；没被忽略、也没加进仓库的文件会被当成问题拦下（需要先提交或删掉）。
- 没有登录功能：只适合在自己电脑上单人使用，不要把端口转发到外网。
- 客户资料以明文 JSON 存在本机，电脑本身要有开机密码等保护。
- 密钥识别靠规则，可能漏判或误判。
- 台账里的回收站没有“永久删除”按钮；真要彻底删除，停服务后手动删 `data/clients/JZ-xxxx.json`。
