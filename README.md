# 建站助手

给做网站的人用的本地客户台账和流程工具：记客户信息 → 准备账号 → 复制开工包，交给云端 Claude 在客户的 GitHub 仓库里做网站 → 记录交付、出交付报告。

网站本身在云端做（Next.js + 21st.dev 组件，依赖只装在云端），这台电脑上只跑台账，不建客户文件夹，也不用装网站的依赖。老客户还可以用原来的“本地文件夹”方式。

需求整理交给 Claude：把和客户聊的录音转文字、截图直接丢给 Claude。建站助手不写网站代码、不运行客户网站、不安装依赖、不提交也不推送代码。

## 启动

需要 Node.js 20 或更新版本。Git 只有老客户的“本地文件夹”方式要用（检查上传、下载继续修改），云端建站不用。**没有第三方依赖，不用 `npm install`。**

- **Windows**：双击 `启动建站助手.cmd`，会自动打开浏览器。
- **Mac**：双击 `启动建站助手.command`，会打开“终端”并自动打开浏览器。第一次运行如果系统提示“无法打开”或“无法验证开发者”，在访达里**右键（或按住 Control 点按）这个文件，选“打开”**，再在弹窗里点“打开”，以后双击就行。如果提示没有权限运行，在终端里进入这个文件夹运行一次 `chmod +x 启动建站助手.command`。
- 或者在这个文件夹里运行：

```bash
npm start
```

然后打开 http://127.0.0.1:4520 。关掉命令行 / 终端窗口（或按 Ctrl+C）就停止。只在本机 `127.0.0.1` 上监听，同一网络里的其他设备访问不到。

## 四个步骤

1. **客户信息**：名字、负责人、电话、地址、邮箱、费用，自动保存。
2. **账号与准备**：买好的域名和每年价格，加一张固定的账号清单（Gmail、GitHub、主仓库、Vercel、域名注册商、Resend、Supabase），每行只填账号名，旁边写着要你自己核实什么。都不强制，填了的才写进交付报告和建站规则。不显示状态，不记密码。账号属于客户，费用由客户承担。
3. **工作环境**：先选建站方式。
   - **云端建站**（新客户默认）：页面上列出开工步骤：用客户的 GitHub 账号建私有仓库、把你的账号加成协作者、给这个仓库装 Claude GitHub App、在 claude.ai 给客户建 Project。然后点“复制开工包”，贴进 Project 的第一条消息。开工包是一段文字：先让云端 Claude 把建站规则存成仓库里的 `CLAUDE.md` 并开 PR，后面是填好店名、编号和账号名的建站规则。建站助手不连 GitHub、不连 Claude，只生成文字。
   - **本地文件夹**（老客户）：一键在 `网站建设` 下新建项目文件夹，写入 `CLAUDE.md`（建站规则：先用 UI UX Pro Max 定设计、客户依据、密钥、推送、交付规矩）。也可以选已有文件夹，同名但内容不同的文件会让你选覆盖（旧的先备份）、另存新版本或取消。规则模板所有客户共用（Next.js、优先用 21st.dev 组件、先用 UI UX Pro Max 定设计、每轮改动开 PR 附截图、不要密钥、做完写 `docs/handoff.md`），可以在这一页改，`{{店名}}`、`{{编号}}` 会自动替换。改过模板的，要点“恢复默认”才会用上新版默认内容。
4. **交付与维护**：记录交付日期（售后从首次交付起算，以后不会被悄悄改；新客户默认售后 0 天，即不含售后）、交付报告（英文，给客户看；打印或存 PDF。固定文字和默认账号清单自动是英文，“交付信息”里自己填的几栏请用英文写。报告里有网站、账号、How to use your website（怎么改内容、客户拥有什么、交付后不含维护）、售后（售后天数大于 0 才显示）、Developer access（云端建站的客户才有：告诉客户你的协作者账号和 Claude GitHub App 交付后还有权限、怎么移除，留不留由客户决定）、价格和付款、平台费用几段；不设签字栏，打印出来在空白处手写签字即可）、维护请求，以及（只有本地文件夹方式的客户才有）**上传检查和清理本地文件夹**：
   - “检查 GitHub 上传”会从 GitHub 取回最新状态，看有没有没提交的改动、没加进仓库的文件、没推送的分支和提交、本地暂存、没推送的标签，并列出被 `.gitignore` 排除、只在本地的文件（例如 `.env.local`、`_原素材/`）。
   - 已记录交付、检查全部通过后，才能“删除本地文件夹”：要输入文件夹名确认；有只在本地的文件要打勾确认；删除前会当场再检查一次。`node_modules`、`.next` 这类能重新生成的直接删，其余整个文件夹移到系统的回收站（**Windows 回收站 / Mac 废纸篓**），需要时可以还原。Mac 上第一次删除时，系统会问是否允许终端控制“访达”，要点“好”；点错了到“系统设置 → 隐私与安全性 → 自动化”里打开。
   - **下载继续修改**：本地没有项目文件夹时（比如交付后清理掉了），填 GitHub 仓库地址（默认用账号清单里的主仓库），把最新代码下载到 `网站建设` 下一个新文件夹，并自动关联成项目文件夹，接着用 Claude Code 改。只下载，不改 GitHub 上的东西；同名文件夹已存在就不下载；只在本地的文件（`.env.local`、`_原素材/`）不在 GitHub 上，要另外放回去。

网址会记住当前客户和步骤（例如 `#/JZ-0001/workspace`），刷新不丢，浏览器“后退”能回上一步；顶栏一直显示保存状态；跟随系统浅色 / 深色模式。界面规范见 `docs/design-system.md`。

## 文件夹

| 位置 | 内容 |
|---|---|
| `server/` | 本机服务（Node 内置模块）；`git.js` 是上传检查和清理 |
| `public/` | 网页界面（原生 JavaScript，不用构建） |
| `shared/` | 浏览器和服务端共用的密钥识别、交付报告说明和“回收站 / 废纸篓”叫法 |
| `tests/` | 验收测试，`npm test` 运行（用临时文件夹和本地裸仓库，不碰真实数据、回收站和废纸篓） |
| `data/` | **客户数据，不提交** |
| `docs/` | 设计规范；交接文件和路线图只留在本机（带客户名，不提交） |

## 数据在哪里、怎么备份

- 每个客户一个文件：`data/clients/JZ-0001.json`。客户之间互不影响。
- `data/clients/*.json.bak`：每次保存前自动留的上一版。
- `data/rules-template.md`：你改过的规则模板（没改过就用内置默认）。
- `data/backups/`：在“工作环境”里选择“覆盖”时，被覆盖文件的旧内容；以及改版前的数据副本。

**备份**：停掉服务，把整个 `data/` 文件夹复制到别处。**恢复**：停掉服务，把备份的 `data/` 放回来再启动。**换电脑**：复制整个 `建站助手` 文件夹（含 `data/`），装好 Node.js 和 Git 就能用。

## 配置

复制 `config.example.json` 为 `config.json` 再改（`config.json` 不提交）：`port`（默认 4520）、`dataDir`（默认 `data`）、`workspaceRoots`（能建 / 选项目文件夹的范围，默认上一级的 `网站建设`；建站助手自己的文件夹永远不能选）。也可以用环境变量 `JZ_PORT`、`JZ_DATA_DIR`，或命令行 `node server/index.js --port=4521 --data=demo-data`。

## 安全设计

- 客户输入一律按纯文本显示；页面有内容安全策略，只运行本机脚本。
- 服务端拒绝未知字段、限制长度；只接受本机页面发来的修改请求。
- 疑似密码、令牌、API 密钥、私钥：浏览器和服务端两处拦截，不保存；写文件前再清一遍。
- 写文件：只在允许范围内的真实文件夹里写，不写链接或联接点，写入前核对文件没被改过，不删除已有文件。
- Git 只用只读命令；关掉 fsmonitor、不弹登录框；显示的远程地址会去掉里面可能带的账号密码。
- 删除本地文件夹只走“检查通过 + 名称确认 + 回收站 / 废纸篓”这一条路；Mac 上文件夹路径作为参数传给系统命令，不拼进脚本；不能删允许范围的根文件夹和建站助手自己。

## 已知限制

- 删除只支持 Windows 回收站和 Mac 废纸篓，Linux 等其他系统不支持。文件夹特别大时，移过去可能要等一会儿。
- “只在本地的文件”靠 `.gitignore` 判断；没被忽略、也没加进仓库的文件会被当成问题拦下（需要先提交或删掉）。
- 没有登录功能：只适合在自己电脑上单人使用，不要把端口转发到外网。
- 客户资料以明文 JSON 存在本机，电脑本身要有开机密码等保护。
- 密钥识别靠规则，可能漏判或误判。
- 台账里的回收站没有“永久删除”按钮；真要彻底删除，停服务后手动删 `data/clients/JZ-xxxx.json`。
